# 定位引擎更新与集成边界

2026-11-16 从 `/home/panhao/Programme/fire-localization-demo-main` 更新八个定位核心模块。社交网络、居民生成和检测属于宿主；定位算法由另一组维护。没有引入源项目的 Bridge、独立 API、CLI 或第二套服务进程。合成帖子生成器仅作为 `tests/localizer_posts_fixture.py` 的离线回归夹具。

## 保留的新版规则

- 原始 90 项与扩展 325 项合成 415 项索引，统一 CITY90x75；原始 LOCAL 对象平移 `[30,25]` 一次，扩展数据不再转换。
- 先按名称/ID/别名唯一匹配，再做严格大于 0.7 的非歧义语义匹配；未匹配或歧义时以发帖位置作参照。
- 半径 15、总张角 45°；预测目标仍为原始八只储罐。`can_post` 是消息来源资格，不是火灾候选白名单。
- 每候选独立 Memory，不合并候选交集。无明确方向且无匹配地点的原帖权重 0.34，其余 1；一致性统计的样本数按真实帖数累计。
- 每候选满 30 分钟无新票退出排名；得分为票数乘非负文本一致性。Top3 分数不是火灾概率。
- 每批 10 条、flush 尾批、摘要去重、批事务和失败 pending 语义保持；新版 Memory 为 schema=3。

## 宿主必要适配

1. `FireLocalizer.__init__` 在新版 `poi_cache_path` 之外保留 `embeddings`、`extractor` 注入，复用宿主 Chat 和专用 Embedding 配置，不加载另一组凭据、不切换离线回退。
2. 通用 Embedding 默认三次尝试保留为可覆盖的 `max_attempts`；宿主设为 1，失败后要求显式重试。成功提取、正文向量及 POI 名称缓存均在会话目录。
3. `LocalizationMemory.restore` 深拷贝 SQLite 确认检查点并校验签名/schema，防止超前工作文件引入未提交票数。规则签名包含算法版本，排除旧合并簇。
4. 宿主保留原帖去重、迟到重放、顺序后台线程、同档旧写入者等待、会话/代际隔离和先保存后推送。过期排名只用已存统计量，不初始化模型。
5. 仿真、居民、地图、报告及预测统一 CITY90x75，预测出口不额外平移。地图使用源项目冻结道路/建筑图层及中央原图，不重新生成几何。
