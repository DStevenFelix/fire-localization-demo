# 本地事件发现

社区群聊下方的“事件发现”展示**疑似危情原帖**。七类为火灾、燃气、交通、积水、建筑及公共设施、治安、人员求助。同一帖子可以命中多类；单人单帖也可以入选。候选不是已确认事故，不输出概率，不自动把不同社区的发帖合并为同一事故。

## 运行流程

```text
各社区本步公开发言
  → EventDiscovery：正文分句、规则召回、语境过滤、公开回复链
  → 所有七类候选：展示及历史保存
  → 新增火灾／燃气候选 + 最多32条必要公开回复上下文
      ├─ 无候选：不请求监测模型，累计一次“跳过监测”
      └─ 有候选：本步统一监测，保留原结构及逐字引用校验
          → 成功报告 → 原有定位 outbox → 另一组的 fire_locator
  → SQLite 提交检查点、消息、发现及报告后，统一发布状态
```

发现模块本身只使用本地 Python 正则和统计，不下载模型，不调用 Chat、Embedding，不读取真实火源、私有感知、话题或 `evidence_signals`。监测和居民仍沿用原有模型配置与启动预检。监测若校验失败，仍按原机制暂停并回滚整步；本地发现不替代监测失败后的输出。定位接口和算法未作修改。

## 规则、语境和上下文

`app/event_discovery.py` 的 `PublicPost` 明确列出输入白名单：正文、公开身份与社区、时间和序号、直接回复ID及公开引用。`RULES` 是七类有名称的静态规则，当前版本为 `local-rules-v1`。

- 明显危险、异常现象和紧急求助可以直接入选。普通“帮忙取快递”不因“帮忙”入选。
- 在分句内检查否定，不用整帖否定。例如“没看到明火，但楼道浓烟很大”仍保留浓烟依据。燃气、设施模式内部的“没有泄漏／没有故障”也检查。
- 历史、演练、影视、知识讨论与普通烹饪语境用于降噪；保留“疑似、不确定、听说、转发”，并给出相应标记。这是有限的规则语境识别，复杂省略、讽刺、跨句转折仍可能误判或漏判。
- 省略直接回复如“具体在哪里”可借用可见父帖；父帖离开展示窗口时，允许使用该帖公开引用。继承线索标为“回复上下文、转述／待核实”，不会认定回复者是另一位独立目击者。“收到、谢谢、没有了”等不会仅因父帖有风险入选。
- 每条依据保存类别、规则名称、原文片段和片段所属消息ID。片段来自正文或公开父帖，没有生成自由文本研判。
- 监测上下文先选择直接父帖，再补公开祖先链，合计最多32条，排除已作为本批候选的重复消息；不附带无关相邻日常聊天。缺失的历史父帖可通过原帖的公开引用提供线索。

修改规则或语义时应更新 `RULE_VERSION`，同时补充人工反例与兼容方案。当前恢复会拒绝未知规则版本，避免把不同规则下的累计统计悄悄混用；这与另一组定位的配置指纹相互独立。

## 窗口统计与界面

时间窗口为 `(当前仿真分钟−15, 当前仿真分钟]`。每类分别统计候选原帖数、不同公开作者数、不同社区数及规范化重复正文量。多类帖子在每个相关类别中各计一次。重复量是该类帖子数减去规范化正文种数；仅去除标点、空白和简单转发前缀，不做语义去重。

这些是**发帖统计**，转述作者也计入作者数，不代表独立证人数或真实风险。热度只作展示，不决定单人报告是否入选。

累计指标和15分钟统计始终覆盖全城；两个筛选器只筛选候选列表，不跟随上方群聊切换。默认显示全城最近50条候选，按消息序号由新到旧；筛选后若近期没有结果，仍可查询“更早记录”。历史每页最多50条，替换当前历史页；“回到最新”返回实时窗口，因此浏览器不无限缓存候选历史。“查看原帖”切换来源社区并打开完整历史详情，原帖离开群聊实时窗口后也可查询。

“火情送检”统计送入监测的火灾／燃气原帖数，不是模型请求数或确认事故数。“跳过监测”统计成功提交且没有相关新增候选的仿真步数。监测输出空事件数组时，送检量仍正常累加。

## 存档和接口

SQLite `user_version=4` 新增：

- `discovery_posts`：完整候选JSON，主键为 `(run_id,message_id)`，每轮消息序号唯一；多类别仍只有一条原帖记录。
- `discovery_categories`：每帖类别关系及分页索引，删除候选时外键级联删除。

新格式不改变地图、居民或定位兼容指纹。旧档只增表和索引，不回扫历史消息。该轮第一次恢复时，以已保存的仿真时间和消息序号为统计起点；随后在检查点中保留起点、累计进度、最近50条和15分钟窗口。页面显示启用时刻。旧消息仍可在原有群聊历史中查看。

完整候选仅在数据库保留，内存只保存最近50条、15分钟窗口的紧凑统计条目和本次待提交候选。时间窗内存随最近15分钟的发帖量变化，不随整轮历史无限增长。本批待提交记录与展示50条分离，避免大批次中较早候选丢失。

整步提交前使用发现状态的临时副本；监测失败不推进累计值、序号或窗口。SQLite事务同时写入群聊、候选、报告和检查点，保存失败恢复最后确认的状态。重复保存按轮次和原帖ID幂等。重启、重置、切档、删除均由现有存档流程管理；删除历史或当前轮次也删除其候选和类别索引。

```http
GET /api/discovery?run_id=<当前轮次>&category=gas&community_id=A-WEST&before=300&limit=50
```

所有参数均可省略；`limit` 默认50，范围1–200，`before` 为排他的消息序号上界，类别使用 `fire/gas/traffic/flood/facility/security/rescue`。返回 `run_id`、`items`（消息序号正序）、`has_more`、`next_before`。过期轮次409，未知社区404，错误类别或分页参数422。完整 `/api/state` 与现有完整状态WebSocket事件中的 `discovery` 同步实时展示数据，无独立模型流。

## 验证与离线评测

`tests/test_event_discovery.py` 覆盖七类正反例、弱线索、多风险、否定、演练、比喻、转述、回复、重复窗口、隐藏标注不变性、零监测请求、送检范围、整步回滚、SQL失败原子性、超过50条的批次、分页、重启、旧档启用点、轮次隔离及删除。现有监测引文校验及定位回归继续执行。

独立浏览器脚本使用测试专属混合公开消息，不修改正式居民生成或非火情真值：

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q -p no:cacheprovider --basetemp=/tmp/socialnet-discovery-tests
PYTHONPATH=.browser-tools/python PLAYWRIGHT_BROWSERS_PATH=.browser-tools/browsers TMPDIR=/tmp python tests/check_discovery_browser.py
PYTHONPATH=. PYTHONDONTWRITEBYTECODE=1 .venv/bin/python tests/evaluate_event_discovery.py --messages 20000 --output .artifacts/discovery-evaluation.json
```

浏览器验证1600、1024和390像素宽度，检查独立滚动、来源详情、筛选、历史分页、动态正文转义、过期响应隔离、切档及重启恢复。测试服务与数据库均独立，不操作正式存档或调用真实模型。静态页面修改无需重建React地图。

`tests/fixtures/discovery_eval.jsonl` 为56条独立人工编写的离线消息，包含33条危情和23条反例；与运行仿真及单元测试文件分开。它是开发用小集，不是盲测集，也不代表真实城市文本分布。逐类结果如下；样本可同时属于多类，因此正例数之和大于候选帖数。

保留的误报是“煤气阀门附近一股刺鼻的味道”：标注仅为燃气，宽召回规则同时命中火灾和燃气。该集候选比例58.93%，火灾／燃气送检原帖占17.86%，送检正文字符较全部正文减少80.39%。这里没有回复上下文，不含固定提示词、输出或token开销，**不能换算为真实费用下降比例**。

工作内存与吞吐的实测原始结果见 `.artifacts/discovery-evaluation.json`：默认把这56条循环扩展到2万条、每批100条推进1个仿真分钟，并启用Python `tracemalloc`。该测量只覆盖本地发现与输入对象构造，不包括居民生成、网络、数据库或整座城市生产负载。窗口稳定后当前内存不随已扫描总数增长，最近候选保持50条。时间及峰值依机器负载变化，复测会覆盖结果文件。

本次实测（2026-11-18）为20,000条／3.733秒，约5,358条/秒，跟踪峰值1.02 MiB；扫描5,000条和20,000条时当前跟踪内存分别约0.78和0.79 MiB，15分钟窗口最多891个紧凑条目，最近候选保持50条。

第一版不扩充正式非火情发帖或真值仿真，因此真实运行的多类样本仍有限。后续应收集有授权且经人工标注的实际社交文本，按类别评估漏筛、误筛及语境问题，再决定是否引入轻量分类器；当前小集的高通过率不能证明真实准确率。
