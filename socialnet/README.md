## 自动保存与恢复

项目自动续存最近一轮仿真到 **runtime/simulation.sqlite3**，无需手动保存。群聊、仿真时间、居民设定、火源及其强度、概率设置、监测报告、定位结果和任务队列一并保存。居民观察记忆、随机状态、消息序号及去重信息也会恢复。存档不包含 API Key；运行时仍读取 .env。

- 每个成功步骤和控制操作自动保存；后台定位在状态变化时独立保存。数据库确认后才向页面发布结果。保存失败会暂停仿真并显示错误，保留上一完整步骤；修复权限或磁盘问题后重启恢复。
- 刷新或重新打开浏览器显示服务器当前状态。后端重启自动恢复为暂停状态，离线时间不推进仿真；点击“开始仿真”或“单步”才继续运行及中断的定位任务。已完成定位不会重新请求或重复计票，原先失败的定位仍需手动重试。
- 页面上方显示“已保存”或“已恢复，等待继续”。完整群聊与报告保存在数据库中；“加载更早消息”“加载更多报告”可以翻阅，较早的引用和关联报告可打开详情。模型仍只使用有限近期上下文，历史分页不会扩展模型记忆窗口。
- “重置仿真”归档上一轮并创建新轮次，旧数据不删除。重启恢复当前活动轮次；开始按钮右侧的“存档”可选择旧记录并载入，也可永久删除记录。
- 数据库采用回滚日志与完整同步，并使用进程锁阻止同一存档被重复打开。不要删除运行中的 simulation.lock；默认不使用多个 Uvicorn worker。SQLite 来自 Python 标准库，无需额外数据库服务。
- 存档包含格式版本和地图、居民定义的兼容标识；不兼容或损坏时明确报错，不静默清空。已有定位 Memory 时，切换模型、Embedding 地址或定位规则会提示定位不兼容；恢复原配置或重置新轮次后再运行。仅更换密钥不改变兼容标识。

首次没有存档时按当前默认配置开始。启用前已被旧版裁剪、未保存的历史无法补回，也不会从零散旧定位审计目录拼接仿真。建议备份前先暂停并停止后端，再复制整个 runtime 目录，包含数据库和定位缓存；恢复时也先停止服务，再使用同一份备份整体还原。

SIMULATION_STORAGE_PATH 可指定独立数据库文件（默认项目 runtime/simulation.sqlite3）；测试应始终指向临时路径，避免载入正式记录。请将此路径放在项目目录内。

## 从旧版升级与恢复

新版启动时，已知旧 48 人定义的存档在取得写锁后自动备份为同目录 `simulation.pre-city-<随机ID>.sqlite3`，再在同一事务中升级活动和归档轮次：平移火源、消息和报告来源坐标，替换整城实体、补齐新增居民/社区及其随机状态。聊天正文、报告证据、序号、旧居民随机流和历史计数保留，恢复后暂停，不按离线时间推进。迁移只执行一次；失败保留旧数据库和备份，不静默清空。不认识的地图/居民定义仍按不兼容处理。

旧定位 Memory 的合并簇 schema=1 与新版独立候选 schema=3 不可直接换算。旧预测只平移用于历史展示，票数不进入新版推理。旧档可载入查看群聊和报告，定位显示不兼容并暂停；要使用新版定位，请重置为新轮次，旧轮次仍在存档中。当前 schema=3 存档若更改模型/规则，继续执行原有严格兼容性检查。

本次更新没有启动正式后端或操作 `runtime/`。部署时先停止旧进程，再用上述启动命令启动新版；旧进程不会自动加载此次代码和地图构建结果。

## 选择与删除存档

点击“开始仿真”右侧的 **存档** 按钮打开列表。每页 20 份，按最近保存时间排序，显示仿真进度、保存时间、完整群聊数、报告数、火源数及“当前使用”标记，可翻页或刷新。不兼容的记录会说明原因并禁止载入，仍可删除。

- **载入**：保存并归档当前轮次，将所选记录重新设为活动轮次，恢复后保持暂停。点击开始或单步才继续；后续更新原存档，不创建副本。仅打开列表或载入不会调用模型。
- **运行中载入或删除当前记录**：停止后续自动推进，等当前这一步完成并保存后再操作；窗口显示等待状态，期间不能重复推进、重置或切换。
- **删除历史记录**：确认后永久删除该轮数据库记录、完整群聊和报告，以及对应定位缓存，不影响当前仿真。
- **删除当前记录**：确认后在同一事务中删除，并创建一份暂停的空白轮次。没有回收站，删除前请确认列表中的时间与数据数量。
- 旧定位请求尚未结束时，列表先移除记录并显示“缓存清理中”；旧请求结束后清理目录。清理失败显示原因并定期重试，重启后继续。缓存仅清理 runtime/localization 下对应轮次目录，不处理其他历史目录。数据库删除后的空闲页可供后续记录复用，不保证文件立即缩小。

普通自动保存现在只允许更新当前轮次，不能隐式切换或归档其他记录。新建、重置、载入、删除及启动恢复在数据库 run_events 表记录时间、操作来源和相关轮次 ID。格式支持从 1/2/3 自动迁移到 4，保留已有活动与归档数据；cleanup_queue 表保存未完成的缓存清理任务。新激活标识与序号用于清理页面缓存、拒绝旧响应，并向其他打开的页面同步切换及删除。

## 模型配置

保留项目根目录现有 .env，不覆盖密钥。居民、监测与定位 Chat 共用已配置的提供商、Key、Base URL 和模型。OPENAI_API_KEY 优先于 DASHSCOPE_API_KEY，原有选择顺序不变。

定位另外需要一个获授权的、OpenAI-compatible Embedding 接口。在 .env 中增加：

```dotenv
LOCALIZATION_EMBEDDING_API_KEY=你的Embedding密钥
LOCALIZATION_EMBEDDING_BASE_URL=你的Embedding服务Base_URL
LOCALIZATION_EMBEDDING_MODEL=你的Embedding模型名称
LOCALIZATION_REASONING_EFFORT=low
```

Base URL 填兼容接口的基础路径，不填完整 /embeddings 地址。不要假定 Chat Key 或模型名也可用于 Embedding，具体以自己的服务权限为准。没有上述三项配置时，定位单独显示缺失配置错误；群聊和监测继续，不猜测服务、不选择 Offline 模型。填写后重启服务，再在定位模块手动重试。

LLM_REQUEST_TIMEOUT_SECONDS 默认 90 秒（5–600），异步居民/监测外层上限再加 5 秒。MONITOR_REASONING_EFFORT 和 LOCALIZATION_REASONING_EFFORT 分别默认 low，仅向兼容的 Qwen3.8 发送该档位；default 表示不传该参数。居民思考参数不变。定位 Chat 和 Embedding 请求不自动重试；失败需手动恢复定位任务，不会偷偷回退本地规则。

.env 修改需重启；已有系统环境变量优先。真实模型运行可能产生费用，测试通过不代表真实网关可用性或准确率已得到验证。

## 仿真和群聊

- 每步推进 5 分钟，10 个居民群独立并行生成；切换页面只改变显示，不控制谁发言。
- 每社区通常一条日常新话题和一条回复；有火源时再安排一条观察，没有感知线索则改为日常话题。社区内部依次生成，回复可引用本轮新消息。
- 在本轮公开烟雾或火光且具有方位信息的观察中，约 60% 分配明确空间表达：正文同时说出完整住宅名称、异常相对住宅的八方位与获准现象。住宅是唯一命名参照，不混入道路、罐区或储罐名称；其余保留仅现象、仅位置、不确定、个人反应、变化或邻居印证等证据层次。只公开气味时不推导方位。
- 火情提示词借鉴示例帖子的空间表达结构，动态示例只使用本轮获准证据。正文仍由千问一次生成，不用示例代替模型输出，不增加 quote 校验或语义重试；无前次观察依据不能描述“越来越浓”“一直没散”。
- 300 人拥有不同姓名、背景、家庭、兴趣、作息和口吻。实时快照每群保留最近 120 条聊天，完整历史另存数据库，总计数不随内存窗口裁剪清零。
- 暂时采用单火源模式：从 8 只储罐登记中心随机选择起火点，同时最多存在 1 处火源。无火源时默认每步概率 30%，三步内首发约 65.7%；出现火源后新增概率固定为 0，手动清除后恢复首发概率，重置仿真清除火源。旧 suppression_factor 字段保留用于接口兼容，当前不生效，界面不再显示倍率滑块。
- 火源持续存在，支持单独/全部清除；每 15 仿真分钟强度增加一级，上限 5。重置归档当前记录，新轮次清空聊天、火源、报告、定位状态并恢复随机流。
- 气味、烟雾、火光按平滑距离权重独立抽样，可同时出现，不是依次升级的互斥等级。它是演示启发式，不是烟气输运、风场或视线物理模型。

居民每条只调用一次模型，直接输出中文正文，不生成 claims/quote，不进行证据位置或措辞的事后拦截与重写；边界在生成提示词中明确。仅空内容、非文本、JSON/代码块等协议错误暂停。提示词不能保证模型绝不越界。监测仍可使用从表达计划和正文词语匹配得出的公开证据标注，群聊卡片显示正文和引用。

居民或监测调用失败/超时仍暂停仿真并回滚本步；没有本地文本或规则回退。两社区版本的旧地图、居民 ID、坐标与缓存不可混用。

## 监测到定位

```text
十个居民群原帖 → 本地事件发现 → 火灾／燃气候选 → LLM 监测报告
                                                ↓
                                   关联居民原帖 → 单一后台定位队列
                                             ↓
                    语义提取 → Embedding/POI匹配 → 空间候选
                                             ↓
                               聚类/投票/文本一致性 → 全局 Top3
```

本地事件发现扫描全部社区的新公开发言，七类疑似危情在群聊下方展示，支持独立社区／类别筛选、来源详情及候选历史。单条弱线索也可以保留，不读取内部话题或真实火源，不调用Chat或Embedding。详细规则、统计及评测见 [EVENT_DISCOVERY.zh-CN.md](EVENT_DISCOVERY.zh-CN.md)。

监测仅分析本步新增火灾／燃气候选和最多32条必要公开回复上下文；无相关候选时跳过模型请求。其余五类只在事件发现展示。监测继续区分亲历、转述、猜测与日常语境。报告保留级别、依据、文本位置线索、逐字引用和待核实项；住址不当作异常地点。报告引用结构校验仍保留，最多请求 4 次（首次加 3 次修正），请求错误立即停止。

只有成功提交的疑似报告会发送定位任务。传的是关联原帖全文，不是报告摘要；字段仅有原帖 ID、仿真时刻、正文、报告者 POI 和由报告级别映射的紧急度。不传真实火源 ID、位置、强度或私有感知。重复报告/原帖不重复投票，后续级别变化也不让旧帖再次计票。

定位每批最多 10 条，不足一批也 flush。提取一个参照物和一个八方位/附近；先匹配唯一名称、ID 或别名，歧义时不强行选第一个，其他参照再做严格大于 0.7 的向量匹配。未匹配时用发帖 POI 作几何参照，这不是请求失败后的离线回退。

采用新版 **15 仿真单位半径、总张角 45° 扇形、30 分钟无新票过期**。每个候选独立维护样本数、向量累计值和票数，不再按候选交集合并。正文既无明确方向、也无匹配地点时，每个命中的候选得 **0.34 票**；其余得 **1 票**。票数以整数百分票累计，文本一致性的样本数仍按真实帖数计算。紧急度保留作审计，不参与当前得分公式。满 30 分钟的等号边界即退出排名，新票为该候选建立新时间窗。输出为 CITY90x75 下八罐的全局 Top3，得分和一致性不是经校准的火灾概率。

15 单位范围遵从另一组最新规则，不再用覆盖全部住宅的半径替代。部分远端居民即使给出正确方向也可能没有候选，不能据此声称所有住宅都能定位到全部储罐。源项目的合成帖子只用于离线回归，不能代表 300 人真实模型群聊的定位命中率。

定位使用原帖的仿真时间，以内部固定纪元换算为分钟时间戳，直接调用引擎而非受真实最近一小时限制的 HTTP 接口。若新报告引用更早的未处理原帖，按原始时间重建定位 Memory；成功的提取及向量有本会话缓存，避免因重建而反复调用。失败批次的 pending 队列保留，重试仍按原帖 ID 去重。

定位完全在后台线程中顺序执行。失败只影响定位：保留最后成功结果并标明，显示错误及重试按钮；新任务等失败任务手动重试后依次处理，不会因新报告到达而偷偷重试。主仿真继续，网络和无效定位输入不会阻止群聊与监测提交。

重置生成新 session_id；未结束的旧网络请求可能仍需等待超时，但结果、Memory、缓存和前端更新均按会话隔离，不回写新场景。服务重启恢复同一轮次的业务状态及已确认的 Memory，运行中的定位任务改为待处理，等待用户继续。不以可能提前写出的工作文件覆盖数据库中的已确认状态；提取与向量缓存仍可复用。

## 定位展示与限制

右侧新增独立火情定位模块，显示状态、原帖数量、证据簇、关联监测报告、每次任务耗时与手动重试。点击 Top3 候选可在共用地图高亮。橙色火焰是真实仿真火源，红环是预测 Top1，黄色虚线环为其他候选；真实火源不参与排名。

当前同时最多一个真实火源；全局 Top3 表示它的三个候选位置，不代表三处真实火源。当前不进行跨报告持久事件关联或每起事件独立定位。分数、相对分数和文本一致性不是经校准的火灾概率；候选为空时不强行给位置。清除真实火源不会依据真值自动删除预测，历史证据按引擎时间窗口自然过期；比较新一轮定位时应重置仿真，以免与上一轮证据混合。

## 接口与数据

- GET /api/state：完整仿真快照，包括定位及 discovery 状态（累计统计、处理进度、15分钟窗口和最近50条候选）。
- GET /api/discovery：按消息序号分页完整候选历史；支持 run_id、before、limit（默认50，1–200）、category、community_id，沿用过期轮次409检查。
- GET /api/localization：独立定位快照，不等待主仿真锁。
- POST /api/localization/{job_id}/retry：仅重试失败定位任务。
- GET /api/runs?page=1&page_size=20：存档摘要列表，返回 items、total、page、page_size、current_run_id、activation_id、activation_sequence、cleanup；page_size 范围 1–100。
- POST /api/runs/{run_id}/activate：正文为 {"expected_run_id":"当前轮次ID"}，返回完整暂停状态；继续更新原记录。
- DELETE /api/runs/{run_id}?expected_run_id=当前轮次ID：永久删除，返回 deleted_run_id、state、cleanup_pending、cleanup。删除当前时 state 是新空白轮次快照，删除历史记录时 state 为 null。
- 存档变更须提供 expected_run_id；页面变更请求还携带 X-Simulation-Activation。活动轮次或激活标识过期、重复切换返回 409，不存在返回 404，数据库写入失败返回 503。
- GET /api/communities/{community_id}/messages：完整消息历史，默认 limit=50，按 before 序号向前分页。
- GET /api/reports：完整报告历史，默认 limit=20，同样支持 before。两个分页接口返回 run_id、items（时间正序）、has_more、next_before；limit 范围 1–200。
- GET /api/messages/{message_id}、GET /api/reports/{report_id}：历史详情，返回 run_id 与 item。历史接口携带 run_id 时必须等于当前轮次，否则返回 409；不存在的对象返回 404。
- 状态新增 persistence（enabled、run_id、saved_at、restored、error、activation_id、activation_sequence）与 report_total；定位状态新增 resume_pending。报告新增单调 sequence，消息原有 sequence 保持连续。
- GET /map-assets/map_original.png：规范底图。
- /ws：仿真事件含 state；定位增量事件 type=localization，含 localization 和 persistence；type=archives 通知刷新存档列表。会话、运行代际、激活标识与序号防止旧请求覆盖重新载入后的状态。
- 原有仿真控制、概率设置与清除火源接口保持可用，文档位于 /docs。

SQLite格式4增加按轮次隔离的发现历史和类别索引。旧档从启用后新消息开始统计，不自动回扫历史；发现与群聊、报告、检查点一起提交或回滚，重置、切档及删除沿用现有生命周期。

runtime/simulation.sqlite3 是业务恢复的权威存档；runtime/localization/<session_id>/ 保存工作 Memory、提取/向量缓存与结果审计，不保存 API Key。请求耗时日志在启动终端中输出，不记录聊天正文、模型原始响应或提供商异常原文。遗留旧状态已备份在 .artifacts/pre-integration-20261104.json，代码备份为同目录 pre-integration-20261104.tar.gz，不会自动导入。

## 验证

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q -p no:cacheprovider --basetemp=.artifacts/pytest-integration
```

包括新版定位引擎核心回归、300 人/10 群、415 项同图坐标、8 罐随机位置与单火源上限、公开原帖隔离、去重、尾批、失败重试、迟到证据重建、缓存、时间过期和重置隔离。模拟模型仅位于 tests，正式应用不提供切换入口。

浏览器集成验证必须使用独立测试服务，不能对真实模型服务运行：

```bash
OPENAI_API_KEY= DASHSCOPE_API_KEY= SIMULATION_STORAGE_PATH=$PWD/.artifacts/mock-simulation.sqlite3 SIMULATION_TEST_RUNTIME=$PWD/.artifacts/mock-localization .venv/bin/python -m uvicorn mock_server:app --app-dir tests --host 127.0.0.1 --port 8011
python tests/check_integration_browser.py --url http://127.0.0.1:8011
```

项目内已有 Playwright 环境时，运行浏览器脚本需设置 PYTHONPATH=.browser-tools/python、PLAYWRIGHT_BROWSERS_PATH=.browser-tools/browsers、TMPDIR=.browser-tools/tmp。测试覆盖原图像素和 POI 对齐、地图点击/缩放/拖动、四群成员、预测叠加、非阻塞失败/重试、旧任务隔离及三种屏幕尺寸。旧伪 3D 浏览器几何断言不再适用，以新的集成脚本为验收入口。

`python tests/check_persistence_browser.py` 会自行启动、停止和重新启动独立模拟后端，使用 .artifacts 下的独立数据库，验证刷新/重启恢复、完整历史加载、旧引用详情、滚动位置和重置后忽略旧分页响应，不访问正式模型。

`python tests/check_run_management_browser.py` 同样自行管理独立模拟后端，验证存档入口、载入无模型请求、等待当前步骤、删除确认及取消、删除当前创建空白、多页面同步、旧激活响应隔离和重启恢复选择，并检查桌面与手机布局。测试数据库与缓存均位于 .artifacts，不操作正式存档。

## 前端构建

运行不需要重新构建。修改 frontend/src 后，在 Node >=22.12 环境执行：

```bash
cd frontend
npm ci
npm run build
```

输出固定为 app/static/spatial/map.js，由现有 FastAPI 服务提供，不额外启动 Vite/Bridge。坐标工具和地图源文件来自新项目并做了宿主集成；来源与边界见 fire_locator/INTEGRATION.md。

`tests/test_event_discovery.py` 验证七类本地筛选、公开信息隔离、监测前置过滤、原子回滚及候选存档。`tests/check_discovery_browser.py` 自行启动独立混合危情测试服务，检查筛选、来源、分页、恢复、过期响应与三种屏宽。`tests/evaluate_event_discovery.py` 使用独立人工离线小集报告逐类指标及吞吐／内存，结果不代表真实城市准确率；命令和限制见 [事件发现说明](EVENT_DISCOVERY.zh-CN.md)。
